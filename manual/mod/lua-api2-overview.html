    22.7 Lua API 2 概览 Lua API 2 Overview

    从 API 版本 2 起（全局变量 GAME_API_VERSION 为 2），游戏为 Mod 脚本提供了一组新接口：载具装配完成的回调、随行为自动结束的事件订阅，以及战场查询、雷达、武器、载具状态等读取接口。它们直接使用游戏自己的数据和事件，比在脚本里扫描场景、按名字递归查找节点或每帧轮询更快，也更可靠。

    From API version 2 onwards (when the global variable GAME_API_VERSION is 2), the game provides a set of new interfaces for Mod scripts: a callback for when vehicle assembly is complete, event subscriptions that end automatically with the behaviour, and read interfaces for querying the battle, radar, weapons, and vehicle status. These interfaces use the game's own data and events directly, making them faster and more reliable than scanning the scene in scripts, recursively finding nodes by name, or polling every frame.

    判断客户端版本 Checking the Client Version

    老版本的客户端没有这些接口，GAME_API_VERSION 为 nil。你的 Mod 需要兼容老客户端时，先判断版本：

    Older versions of the client do not have these interfaces; GAME_API_VERSION is nil. When your Mod needs to be compatible with older clients, check the version first:

    Behavior()
Property = {}

local MyBehavior = class("MyBehavior")

function MyBehavior:OnStarted()
  -- 老客户端没有 API 2：GAME_API_VERSION 为 nil / Older clients have no API 2: GAME_API_VERSION is nil
  if (GAME_API_VERSION or 1) < 2 then
    print("[MyBehavior] this mod needs a newer game client")
    return
  end
end

function MyBehavior:OnVehicleReady(vehicle)
  -- 所属载具装配完成后调用一次；车库里也会调用
  -- Called once when the vehicle is assembled, in the garage too
  self.vehicle = vehicle

  if VehicleAPI.IsGarage(vehicle) then
    -- 车库里不需要战斗逻辑 / No battle logic in the garage
    self.script:SetUpdateEnabled(false)
    return
  end

  -- 每 0.2 秒调用一次 OnUpdated / Call OnUpdated every 0.2 s
  self.script:SetUpdateInterval(0.2)
end

function MyBehavior:OnUpdated(dt)
  -- dt：距上次调用的秒数 / dt: seconds since the previous call
end

function MyBehavior:OnVehicleDestroyed(vehicle)
  -- 所属载具被击毁 / The vehicle was destroyed
end

function MyBehavior:OnDestroyed()
  -- 用 self.script 订阅的事件随后自动退订，不用手动注销
  -- Subscriptions made with self.script end right after this; nothing to unregister
end

return MyBehavior

    行为回调 Behaviour Callbacks

    回调 Callback 何时调用 When it runs
    OnStarted() 脚本运行后立即调用。挂在载具上时，载具可能还没装配完。
    Right after the script runs. On a vehicle, the vehicle may not be assembled yet.
    OnVehicleReady(vehicle) 所属载具装配完成后调用一次；脚本运行时载具已经装好的话，紧接在 OnStarted 之后调用。车库里也会调用。不在载具上的行为（地图、特效）不会收到。
    Once, when the owning vehicle is assembled; right after OnStarted if it already is. Also in the garage. Behaviours not on a vehicle (maps, effects) never get it.
    OnUpdated(dt) 每帧调用，或按 SetUpdateInterval 的间隔调用；dt 是距上次调用的秒数。
    Every frame, or at the interval set with SetUpdateInterval; dt is the time since the previous call.
    OnVehicleDestroyed(vehicle) 所属载具被击毁时。
    When the owning vehicle is destroyed.
    OnDestroyed() 行为销毁时。之后本行为的事件订阅全部自动结束。
    When the behaviour is destroyed. Its event subscriptions all end right after.

    挂在载具数据上的行为（载具、炮塔、武器的 Lua 行为），在 OnStarted 里就能读到游戏传入的属性：坦克的这些行为都有 self.vehicle，炮塔上的行为有 self.turretController，坦克武器上的有 self.tankFire，飞机武器上的有 self.flightFire。任何行为都可以用 self.script:GetVehicle() 取得所属载具。

    Behaviours attached to vehicle data (Lua behaviours for vehicles, turrets, and weapons) can read the properties passed by the game in OnStarted: these behaviours on tanks all have self.vehicle, behaviours on turrets have self.turretController, those on tank weapons have self.tankFire, and those on aircraft weapons have self.flightFire. Any behaviour can obtain its parent vehicle using self.script:GetVehicle().

    self.script

    方法 Method 作用 Purpose
    self.script:GetVehicle() 所属载具（坦克、飞机、步兵都适用），不在载具上时为 nil。结果会缓存，可以每帧调用。
    The owning vehicle (tank, aircraft or infantry), or nil. Cached, so it is fine every frame.
    self.script:SetUpdateInterval(seconds) OnUpdated 的调用间隔，0 为每帧。间隔内的帧不会调用 Lua。
    How often OnUpdated runs; 0 means every frame. Frames in between do not call Lua.
    self.script:SetUpdateEnabled(false) 完全停止调用 OnUpdated；事件回调和 OnGUI 不受影响。传 true 恢复。
    Stops calling OnUpdated; event callbacks and OnGUI keep working. Pass true to resume.

    事件订阅 Event Subscriptions

    所有新事件的写法相同：XxxAPI.OnSomething(self.script, target, callback)，依次传入 self.script、目标和回调，返回一个订阅对象。

    All new events follow the same syntax: XxxAPI.OnSomething(self.script, target, callback), passing self.script, the target, and the callback in order, which returns a subscription object.

    local sub = WeaponAPI.OnAmmoChanged(self.script, weapon, function()
  self:Refresh()
end)

-- 想提前停止时 / To stop earlier:
-- sub:Dispose()

    • 传入 self.script 的订阅在行为销毁时自动结束，不用在 OnDestroyed 里手动注销。

    • 目标载具被移除时，订阅也会自动结束。

    • 游戏模式脚本和依赖库没有 self.script，可以传 nil；这样的订阅在退出游戏模式时自动结束。

    • sub.IsActive 表示订阅是否仍然有效。

    • 回调连续出错 10 次后会被停用，日志里会写明是哪个脚本。

    • Subscriptions made with self.script end automatically when the behaviour is destroyed; you do not need to manually unregister them in OnDestroyed.

    • Subscriptions also automatically end when the target vehicle is removed.

    • Game mode scripts and dependency libraries do not have self.script; you can pass nil. Such subscriptions automatically end when the game mode is exited.

    • sub.IsActive indicates whether the subscription is still valid.

    • If a callback errors out 10 times consecutively, it will be disabled, and the log will specify which script caused it.

    约定 Conventions

    • 传入 nil、已销毁的对象或越界的序号时，接口返回 false、0 或 nil，不会报错，不需要再用 pcall 包住每一行。

    • 读取类接口每次调用都不产生垃圾。会分配内存的只有 CreateQuery、FindAllDeep 这类初始化接口，请只在初始化时调用一次。

    • 联机对战中，读取其他载具的接口只返回你的队伍当前看得见的敌人；雷达目标本身已经经过探测判定。

    • 控制类接口（例如雷达锁定）只对玩家正在控制的载具生效，对其他载具返回 false。

    • When passing nil, a destroyed object, or an out-of-bounds index, the interfaces return false, 0, or nil without throwing an error, so you do not need to wrap every line in pcall.

    • Read interfaces do not generate garbage on every call. Only initialisation interfaces like CreateQuery and FindAllDeep allocate memory; please call them only once during initialisation.

    • In online battles, interfaces that read other vehicles only return enemies currently visible to your team; radar targets have already undergone detection checks.

    • Control interfaces (such as radar lock) only work on the vehicle currently controlled by the player and return false for other vehicles.

    性能建议 Performance Tips

    下面这些是 Lua 审核里最常见的性能问题和对应的写法：

    These are the most common performance problems found by the Lua audit, and what to do instead:

    • 不要每帧扫描整个场景（GetObjectsInWorld、FindObjectsOfType）来找载具，用 VehicleAPI.CreateQuery()。

    • 不要每帧递归查找节点。在 OnVehicleReady 里用 TransformAPI.FindDeep 找一次；找不到就说明模型上没有，不要重试。

    • 不要在 OnUpdated 里反复重试初始化，把初始化放进 OnVehicleReady。

    • 不需要每帧执行的逻辑，用 SetUpdateInterval 降低频率；完全靠事件驱动的脚本，用 SetUpdateEnabled(false) 关掉 OnUpdated。

    • 弹药、装填、模块、起落架、雷达锁定这些状态变化都有事件，不要轮询。

    • Do not scan the entire scene every frame (GetObjectsInWorld, FindObjectsOfType) to find vehicles; use VehicleAPI.CreateQuery().

    • Do not recursively find nodes every frame. Use TransformAPI.FindDeep once in OnVehicleReady; if it is not found, it means it is not on the model, so do not retry.

    • Do not repeatedly retry initialisation in OnUpdated; put initialisation in OnVehicleReady.

    • For logic that does not need to run every frame, use SetUpdateInterval to lower the frequency; for scripts that are entirely event-driven, use SetUpdateEnabled(false) to turn off OnUpdated.

    • Ammo, reload, module, landing gear and radar lock changes all have events; do not poll them.
