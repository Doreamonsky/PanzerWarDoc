    官方模组仓库

    1. 在模组仓库的 GitHub Actions 中打开 Build modpack。填写受影响的 packs 与目标 platform。
    2. 验收构建时设置 publish=none，留空 release。工作流会裁剪依赖、拉取相应的 LFS、构建并验证。
    3. 从该次运行的 Artifacts 下载 .modpack 与同名 .modpack.json，核对平台、GUID 和版本。

    SDK 工程中的本地构建清单

    1. 在 ModPackageBuildPiplineData 中引用 ModPackageData 和要打包的资源。
    2. 在 JSON 的 infos 新增一项。把要一起构建的管线加到 modNames。直接位于 Assets/ModManager 的资产可以只填名称。位于子目录时写从工程根开始的完整资产路径，包括 .asset 后缀。
    3. 将每个平台的输出加到 copyInfo。当前活动平台为 Android 时只处理 Android 条目，为 StandaloneWindows64 时只处理 Windows 条目。先创建输出目录。isPackage=true 输出 .modpack。使用原始资源目录的流程可填 false。多个管线共用一个输出目录时，保持 isCleanDstFolder=false。设为 true 会在每个管线复制前清理目标目录。
    {
  "infos": [
    {
      "modNames": [
        "BuildPipline-Lua-ModeRes",
        "Assets/ModManager/Vehicles/BuildPipline-Vehicles.asset"
      ],
      "copyInfo": [
        { "platform": "Android", "dstDir": "Build/Ship/Android" },
        { "platform": "StandaloneWindows64", "dstDir": "Build/Ship/Windows" }
      ],
      "isPackage": true,
      "isCleanDstFolder": false
    }
  ]
}
    1. 从编辑器入口调用 ShanghaiWindy.Editor.Utility_BuildPipline.BuildPiplineManifest(path)。核对相应目录的归档。可用 Frontend.Editor.ModPackageWorkshopMeta.WriteSidecar(archivePath) 生成同名 .modpack.json，再核对平台、GUID 与版本。

    在命令行运行

    旧版 DoBuildPiplineManifest -config 入口已变更。使用一个无参数的静态 Editor 方法作为 Unity 的 -executeMethod 入口，在方法内读取清单位置并调用 BuildPiplineManifest(path)。命令行传入 Unity 安装路径、项目根目录、目标平台、入口方法与日志路径。Windows 可在 PowerShell 或 Git Bash 运行。完整命令见 Jenkins 自建构建。
