    用 FMOD Profiler 录制音频事件

    中文 | English

    在仓库根目录运行以下命令，用本机 Unity MCP 回放本页示例。

    python Docs/Manual/manual/tools/tutorials.py run fmod-profiler

    Profiler 可以记录音频事件、音量、CPU 与内存。先准备 FMOD 工程和 Bank，并在 Unity 加载能播放待检查声音的场景。

    1. 启用实时连接

    1. 在 Unity 打开 FMOD → Edit Settings，选择正在测试的平台。编辑器用 Play in Editor，独立构建用对应平台。启用 Live Update 并查看 Live Update Port。FMOD 的默认端口是 9264，本工程测试时读取到 9000。连接时用当前平台显示的值。若改的是独立程序设置，改完后重新构建。
    点击展开 MCP 操作点击收起 MCP 操作

    1. 在 FMOD Studio 打开构建这些 Bank 的工程。在 Unity 进入 Play Mode，或启动刚构建的测试程序。
    2. 在 Studio 选择 File → Connect to Game。同一台电脑输入 localhost:<端口>，例如 localhost:9000。另一台测试设备用该设备的地址与端口。连接成功后右下角显示绿色 Live Update ON。FMOD 连接说明

    2. 录制并定位音量问题

    1. 在 Studio 打开 Window → Profiler，点圆形 Record 开始录制。在 Unity 复现问题一次，然后点 Stop。
    2. 在时间轴找出复现的时段。左侧选事件轨，查看该段的事件实例和音量，再对照同一段的 Mixer CPU 与内存使用。
    3. 打开 Window → Mixer，沿事件输出路由查看子总线及主总线的电平。听运行中的游戏声音，与 Studio 本地试听或已有的参考录音对比。
    4. 如果事件触发正常但声音不对，分别检查源文件电平、事件和总线增益、Unity 音量设置。保存会话，改一项设置后再录一段对比。Studio 本地试听也可以直接录制。FMOD Profiler 说明

    上方的 MCP 操作读取 Unity 平台的连接设置。连接和录制在 FMOD Studio 完成。
