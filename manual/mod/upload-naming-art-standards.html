    美术资源命名与上传规范

    中文 | English

    一次提交应围绕一项连贯的改动，并为资源使用有明确含义的名称。以下规范适用于官方资源仓库里的载具、地图和共享资源。

    1. 分支范围

    每个分支应尽可能减少改动，理想情况下一个分支只改一辆坦克或一架飞机。不要在一个分支里囤积大量载具改动再请求合并，这样的合并不会被接受。范围小的分支便于逐个复核、定位问题和回退。

    2. 命名规范

    1. 文件名以大写字母开头，例如 PantherTurret.fbx，而不是 pantherTurret.fbx、panther turret.fbx 或全大写的 PANTHERTURRET.FBX。
    2. 名称要能说明这是什么，避免 asdf.fbx、NewFile2.fbx 这类随手写出的字符串。同一部件的模型、贴图、材质和预制体沿用同一组词。
    3. 注意拼写，例如 Turret 不要写成 Turet，Receiver 不要写成 Reciever。导出前统一检查一遍文件名。

    3. 修改现有模型时替换 FBX

    在建模软件里导出新的 FBX，直接覆盖原有路径上的 FBX 文件：可以在导出时指定同一个文件名，也可以在文件夹里把新文件复制过去覆盖。这个操作无法在 Unity 编辑器内完成。

    覆盖时保留原来的 .meta，以便 Unity 继续用同一个 GUID 识别 FBX。重命名或重建子网格可能改变子资源的本地 ID。导入后逐项检查 prefab 的网格引用、材质槽和相关节点。若删除 .meta 或另建不同路径的 FBX，Unity 会生成新的 GUID。

    如果在 FBX 里新增了模型，把重新导入的 FBX 拖进一个空场景，再把新增的部分复制进原本的预制体并保存。不要因为只是多了一块模型就新增一个 FBX 文件，否则会留下 XXX_fix.fbx、XXX_fix2.fbx 之类的文件，让工程变得混乱。

    4. 法线贴图与基础色贴图分开

    法线贴图和基础色（RGB）贴图必须是两张独立的贴图，不要用一张贴图同时充当两者。在建模软件里，不要让 RGB 贴图接到 Normal 输入上；在 Unity 里把法线贴图的 Texture Type 设为 Normal map，再把基础色贴图接进 Base Color 输入，两个输入各自指向自己的贴图。

    旧指南里的“不要设置 Normal 强度”针对的是导入的材质：保持默认的 Normal 强度即可，不要为单个模型随手改动这个值。Unity 的着色器本身有 Normal strength / Bump scale 参数，规范要求的是不要在导入的模型上做无依据的逐模型覆盖。

    5. 避免重复材质

    重复材质指使用完全相同贴图的多个材质球，它们会增加渲染开销，也让后续统一修改容易漏掉对象。

    同一 .blend 中用 Shift+D 复制物体。跨文件粘贴后检查材质引用，确认没有多出一份使用相同贴图的材质。

    已经存在的重复材质需要手动统一：把每个对象的材质引用替换为同一个材质，使其指向共享材质。材质下拉框会列出可选的材质，重复的通常以 .001、.002 结尾；也可以在上方的搜索框里按名称查找这些重复项。

    在临时目录用两张纹理检查法线导入和覆写后的资产 GUID。FBX 内部子网格的引用另按正文复核。

    [
  {
    "tool": "invoke",
    "arguments": {
      "path": "static:ShanghaiWindy.Core.AssetBundleManager/LuaEnv/DoString",
      "args": [
        "\nlocal u, e, io = CS.UnityEngine, CS.UnityEditor, CS.System.IO\nlocal base = \"${fixture}/TutorialTank_BaseColor.png\"\nlocal normal = \"${fixture}/TutorialTank_Normal.png\"\nlocal tex = u.Texture2D(2, 2, u.TextureFormat.RGBA32, false)\nlocal function write(path, r, g, b)\n    for x=0,1 do\n        for y=0,1 do\n            tex:SetPixel(x, y, u.Color(r,g,b,1))\n        end\n    end\n    tex:Apply()\n    io.File.WriteAllBytes(path, u.ImageConversion.EncodeToPNG(tex))\n    e.AssetDatabase.ImportAsset(path, e.ImportAssetOptions.ForceSynchronousImport)\nend\nlocal ok, issue = pcall(function()\n    write(base,0.7,0.6,0.5)\n    write(normal,0.5,0.5,1)\n    local baseGuid = e.AssetDatabase.AssetPathToGUID(base)\n    assert(baseGuid ~= \"\" and baseGuid ~= e.AssetDatabase.AssetPathToGUID(normal))\n    local baseImporter = e.AssetImporter.GetAtPath(base)\n    baseImporter.textureType = e.TextureImporterType.Default\n    baseImporter.sRGBTexture = true\n    baseImporter:SaveAndReimport()\n    local normalImporter = e.AssetImporter.GetAtPath(normal)\n    normalImporter.textureType = e.TextureImporterType.NormalMap\n    normalImporter.sRGBTexture = false\n    normalImporter:SaveAndReimport()\n    write(base,0.2,0.4,0.6)\n    assert(e.AssetDatabase.AssetPathToGUID(base) == baseGuid)\n    assert(e.AssetImporter.GetAtPath(base).sRGBTexture)\n    assert(e.AssetImporter.GetAtPath(normal).textureType == e.TextureImporterType.NormalMap)\n    assert(not e.AssetImporter.GetAtPath(normal).sRGBTexture)\nend)\nu.Object.DestroyImmediate(tex)\nassert(ok,issue)\nreturn \"Independent texture imports verified; overwrite kept original asset GUID\"\n",
        "art-import-sample",
        "null"
      ]
    },
    "expect": {
      "contains": "overwrite kept original asset GUID"
    }
  }
]
