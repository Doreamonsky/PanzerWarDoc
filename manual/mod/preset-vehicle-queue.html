    内置载具队列是随模组打包的资源资产，列出比赛可提供的载具，游戏内只读，也是战斗配置选车界面的输入。

    不要与 PresetVehicleQueueConfig 混淆：后者是玩家存档配置，不是需要打包的资产。

    1. 创建资产

    Assets > Create > A Panzer War - 装甲纷争 > G Ground Vehicle - 地面载具 > Base - 载具配置 > Vehicle Queue - 载具队列
    点击展开 MCP 操作点击收起 MCP 操作 
    [
  {
    "tool": "invoke",
    "arguments": {
      "path": "static:UnityEditor.AssetDatabase/CreateAsset",
      "args": [
        "@static:UnityEngine.ScriptableObject/CreateInstance(ShanghaiWindy.Core.BuiltInVehicleQueueData)",
        "${asset}"
      ]
    },
    "expect": {
      "contains": "OK:"
    }
  },
  {
    "tool": "inspect_set",
    "arguments": {
      "path": "static:UnityEditor.Selection/activeObject",
      "value": "@asset:${asset}"
    },
    "expect": {
      "contains": "OK:"
    }
  }
]

    2. 设置匹配标识与名称

    • 唯一标识（guid） — tutorial-queue-001；普通字符串，非 Unity 资源 GUID
    • 载具队列类型（vehicleQueueType） — 选择 匹配 - Match 枚举
    • 载具队列名称（queueName） — 展开后把其中的 默认名称（defaultName）设为 Tutorial Queue

    guid 为空时会自动生成。实际发布时，各队列的标识应保持唯一、稳定；不要给多个队列照抄图中的 tutorial-queue-001。

    点击展开 MCP 操作点击收起 MCP 操作

  {
    "tool": "inspect_set",
    "arguments": {
      "path": "asset:${asset}/guid",
      "value": "tutorial-queue-001"
    },

      "contains": "OK:"
    }
  },
  {

    "arguments": {
      "path": "asset:${asset}/vehicleQueueType",
      "value": "Match"

    "tool": "inspect",

      "path": "asset:${asset}/vehicleQueueType"

    "expect": {
      "contains": "Match"
    }
  }
]

    3. 添加一个载具条目

    在 载具标识列表（vehicleGuids） 点 + 添加一条，然后填写两个字符串：备注（comment） 为作者备注，载具唯一标识（vehicleGuid） 为载具加载标识。

    该标识即 VehicleInfo 对外提供的标识：assetGuid，为空时回退为小写的 vehicleName。请从你自己的可驾驶 VehicleInfo 复制；不要使用 Unity .meta GUID 或 VehicleTextData.editorAssetGuid。

    选中对应的 VehicleInfo，点击 拷贝资源标识，再把复制的值粘贴到 vehicleGuid。

    有现成载具时，也可以在游戏车库打开该车的 载具数据，在 Overview 中点 Copy，复制运行时读取的同一个标识。

    示例 comment 为 T-34-85 No.215，vehicleGuid 为 a922ecf1-f7ce-45f9-b0f8-86a23ec26c2c，来自官方 AAA2 内容，仅为演示，不会自动提供到你的工程。

    该列表是可用载具集合，不是数量：条目数就是条目数量，没有出场数量字段。实际出场数量由模式设置决定。

    点击展开 MCP 操作点击收起 MCP 操作

    为复现复制 GUID 操作，准备阶段只重建了官方 T-34 的名称/载具 ID 元数据；它不含模型，不加入模组包，也不能驾驶。发布时必须选择真正的可驾驶 VehicleInfo，并包含其内容或依赖。列表整体 JSON 赋值对应添加和填写条目，没有数量字段。

    [
  {

    "arguments": {
      "path": "asset:${vehicleInfo}/GetLoadGUID",
      "args": []

    },

        "regex": "\\(String\\) (.+)"
      }
    }
  },
  {
    "tool": "inspect_set",
    "arguments": {
      "path": "asset:${asset}/vehicleGuids",
      "value": "[{\"comment\":\"T-34-85 No.215\",\"vehicleGuid\":\"${vehicleGuid}\"}]"
    },
    "expect": {
      "contains": "OK:"
    }

  {
    "tool": "inspect",
    "arguments": {
      "path": "asset:${asset}/vehicleGuids/0/vehicleGuid"
    },
    "expect": {
      "contains": "${vehicleGuid}"
    }
  }
]

    4. 打包并带上载具内容

    • 资产的 guid 作为包名，variant 为 vehiclequeue，打包为 <guid>.vehiclequeue
    • 把资产加入模组构建管线的资源数组（字段 linkedObjects）
    • 条目是字符串，不会自动带上载具：请把被引用载具的内容放入本包或已安装依赖中
    点击展开 MCP 操作点击收起 MCP 操作

    5. 在战斗配置中选用并排查

    内置队列在当前选车界面与玩家自建队列一同列出，游戏内只读；修改已发布队列需编辑资产并重新打包。队列查找覆盖房间预设、战区配置与内置 Match 队列，因此本教程保持 Match。

    资产默认类型为 Lobby，但当前战斗配置选车界面不使用该列表，需要手动改为 Match。

    队列不显示条目的常见原因：字符串匹配不到已注册的 VehicleInfo、载具不可驾驶、无法在当前地图出生，或载具内容不在本包及其依赖中。此时应检查标识、依赖内容与载具的可选条件。

    本页的菜单路径、字段名与行为来自源码及资产检视；两张图为真实编辑器截图。共享配方已验证队列定义包的 Windows 构建、ZIP 清单与 sidecar；包内不含 T-34 模型，未执行安装或游戏内运行。
