    模组镜像站点搭建

    中文 | English

    镜像站把允许转发的工坊存档放成一份可以直接下载的目录，减轻官方下载器的流量压力，也让玩家在官方站点不稳定时仍能取得同样的包。存档的完整性、平台归属和文件名都要保持原样。

    历史：旧的 JSON 列表

    早期方案以上述公开列表作为镜像的索引：

    https://dl-workshop.windyverse.net/packages/files_list.json

    该 JSON 记录模组名称、更新日期和下载链接，服务端每 12 小时刷新一次。配套的 Python 辅助脚本按列表批量下载全部模组，并依赖 requests 与 tqdm，另外用 downloaded_files.json 记录已下载的地址、用 tmp 暂存未完成的文件。这些都是当时的描述，不必照搬脚本：现在可以直接取用存档，索引只作背景。

    2026-11-18 对该地址的 GET 返回 HTTP 404。此后它只说明旧方案的形状，不再是镜像内容的来源或权威清单。

    归档允许转发的工坊存档

    只放你有权再分发的工坊存档。下载后原样保存，不改名、不重新打包压缩包，也不要为了凑目录而复制其它平台的包。

    packages/
  android/
  win64/
  ios/

    每个平台一个文件夹，放入对应平台构建的 .modpack。文件名保持发布时的原名。有同名 .modpack.json 时一并保留，方便核对平台、版本、GUID 和内容元数据。完整文件清单在归档内的 package.json 中。每个平台使用自己的构建。

    用网盘做镜像

    以 UC 网盘为例，让客户端自动同步 packages 文件夹到云端。同步完成后再共享该文件夹，并设为只读分享，避免读者误删或改动原目录。共享链接只指向 packages，不要混入生成过程中的临时目录。

    静态托管替代方案

    也可以通过 Nginx 或其他静态托管提供下载。先在包含 packages 的上级目录做本机预演：

    python -m http.server 8080 --bind 127.0.0.1

    打开 http://127.0.0.1:8080/packages/win64/，下载一个实际文件，确认文件名和目录正确。预演完成后按 Ctrl+C 停止。正式托管使用相同的目录结构，给玩家提供可直接下载的只读链接。

    同步后验收

    1. 等待同步或部署结束，不要在同步途中就把链接发出去。
    2. 用普通读者身份打开分享链接，下载一个样例 .modpack，确认不需要登录或特殊权限。
    3. 分别对源文件和下载副本运行 PowerShell 的 Get-FileHash -Algorithm SHA256 -LiteralPath "<文件路径>"。两份哈希应相同。有 .modpack.json 时一并核对平台、版本和 GUID。
    4. 确认无误后，让玩家按安装模组把包放进游戏的安装队列。

    镜像只提供安装包，不含开发工具。公开 SDK 是开发工程，其下载方式见项目下载参考。
