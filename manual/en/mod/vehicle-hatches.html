    Vehicle Hatch Configuration Tutorial

    中文 | English

    Run this command at the repository root to replay the examples through the local Unity MCP. The command also captures screenshots in both languages.

    python Docs/Manual/manual/tools/tutorials.py run vehicle-hatches --capture
    Click to expand MCP actionsClick to collapse MCP actions

    Prepare the teaching sample. The recipe provides ${variables}.

    {
  "variables": {
    "asset": "${fixture}/Tutorial_Hatch.prefab",
    "sourceMesh": "${fixture}/Tutorial_HatchSource.obj"
  },
  "calls": [
    {
      "tool": "invoke",
      "arguments": {
        "path": "static:UnityEditor.AssetDatabase/CreateFolder",
        "args": [
          "${fixtureParent}",
          "${folder}"
        ]
      },
      "expect": {
        "regex": "\\(String\\) [a-f0-9]{32}"
      }
    }
  ]
}

    This tutorial uses a separate Tutorial_Hatch.prefab to show hatch markers, moving parts and double-sided meshes. The example contains teaching nodes and a mesh rather than a complete vehicle. Field spellings match the source.

    1. Add and register the component

    • Add VehicleHatchAttachmentMonoComponent to the hatch object and expand hatchAttachmentSlot.attachment to edit its nested configuration.
    • On the same object, configure VehicleAttachmentMonoComponent for runtime discovery: set attachmentSlotType to Specific and assign the hatch component to specificAttachmentMonoComponent. The project's CustomEditor adds this companion automatically; the recipe creates and saves it explicitly.

    Check that the companion references the current hatch component.

    2. Hatch centre, hand markers and hinge

    • hatchRadius=0.5; hatchTransform is the hatch opening centre.
    • leftHandSlotTransform and rightHandSlotTransform are hand placement markers, not the moving hinge or pivot.
    • The moving pivot is each activeParts entry's activePartTransform: assign the independent moving pivot to activePartTransform with identity initial local rotation.

    Expected check: the hatch centre sits at the opening, hand markers are not used as hinges, and the pivot starts at identity rotation.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "prefab_edit",
    "arguments": {
      "json": {
        "path": "${asset}",
        "mode": "update",
        "component": "ShanghaiWindy.Core.VehicleHatchAttachmentMonoComponent",
        "values": {
          "hatchAttachmentSlot": {
            "attachment": {
              "hatchRadius": 0.5
            }
          }
        },
        "references": [
          {
            "property": "hatchAttachmentSlot.attachment.hatchTransform",
            "child": "HatchCenter"
          },
          {
            "property": "hatchAttachmentSlot.attachment.leftHandSlotTransform",
            "child": "LeftHand"
          },
          {
            "property": "hatchAttachmentSlot.attachment.rightHandSlotTransform",
            "child": "RightHand"
          }

    3. Configure movement

    • isSemiOpen=false shows activeParts.
    • Each entry uses axis=(1,0,0), activeAngle=90, closeAngle=0, moveSpeed=120.
    • At runtime localRotation=Quaternion.AngleAxis(angle,axis) overwrites the local rotation; it does not add a delta.
    • isSemiOpen is a state or display condition; setting it does not guarantee runtime code disables existing activeParts animation.

    Expected check: the pivot starts at identity rotation, so the result does not depend on the original orientation.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "prefab_edit",
    "arguments": {
      "json": {
        "path": "${asset}",
        "mode": "update",
        "component": "ShanghaiWindy.Core.VehicleHatchAttachmentMonoComponent",
        "values": {
          "hatchAttachmentSlot": {
            "attachment": {
              "isSemiOpen": false,
              "activeParts": [
                {
                  "axis": {
                    "x": 1,
                    "y": 0,
                    "z": 0
                  },
                  "activeAngle": 90,
                  "closeAngle": 0,
                  "moveSpeed": 120
                }
              ]
            }
          }
        },
        "references": [
          {
            "property": "hatchAttachmentSlot.attachment.activeParts.Array.data[0].activePartTransform",
            "child": "HatchPivot"
          }
        ]
      }
    },
    "expect": {
      "equals": {
        "ok": true
      }
    }
  }
]

    • Verify the component, pivots and movement values, including the runtime discovery condition.

    5. Bake double-sided meshes when needed

    If an open hatch needs visible backfaces, assign the relevant MeshFilter entries to doubleSidedMeshFilters. In the vehicle attachment configuration editor, click the double-sided mesh bake button and choose an output folder under Assets. doubleSidedMeshes is generated output, not a list to fill manually. Limit this to the moving regions that need backfaces to avoid doubling the entire vehicle's triangle count.

    The recipe demonstrates the input and output references with a separately copied quad mesh. It calls the same baker with an explicit output folder, bypassing the interactive folder dialog. Repeated baking updates generated meshes while preserving GUIDs. Temporarily enabled source Read/Write settings are restored afterwards. This verifies mesh data and references, not the final rendered appearance.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "invoke",
    "arguments": {
      "path": "static:UnityEditor.AssetDatabase/CopyAsset",
      "args": [
        "Packages/com.shanghaiwindy.coreresources/Light/AuthoringSamples/Square.obj",
        "${sourceMesh}"
      ]
    },
    "expect": {
      "contains": "True"
    }
  },
  {
    "tool": "prefab_edit",
    "arguments": {
      "json": {
        "path": "${asset}",
        "mode": "update",
        "component": "UnityEngine.MeshFilter",
        "child": "HatchPivot/HatchMesh",
        "references": [
          {
            "property": "m_Mesh",
            "asset": "${sourceMesh}",
            "type": "UnityEngine.Mesh"
          }
        ]
      }
    },
    "expect": {
      "equals": {
        "ok": true
      }
    }
  },
  {
    "tool": "prefab_edit",
    "arguments": {
      "json": {
        "path": "${asset}",
        "mode": "update",
        "component": "ShanghaiWindy.Core.VehicleHatchAttachmentMonoComponent",
        "values": {
          "hatchAttachmentSlot": {
            "attachment": {
              "doubleSidedMeshFilters": [
                {}
              ]
            }
          }
        },
        "references": [
          {
            "property": "hatchAttachmentSlot.attachment.doubleSidedMeshFilters.Array.data[0]",
            "child": "HatchPivot/HatchMesh",
            "component": "UnityEngine.MeshFilter"
          }
        ]
      }
    },
    "expect": {
      "equals": {
        "ok": true
      }
    }
  },
  {
    "tool": "invoke",
    "arguments": {
      "path": "static:ShanghaiWindy.Editor.VehicleHatchMeshBaker/BakePrefab",
      "args": [
        "${asset}",
        "",
        "${fixture}"
      ]
    },
    "expect": {
      "contains": "_DoubleSided_"
    }
  },
  {
    "tool": "inspect",
    "arguments": {
      "path": "asset:${asset}/GetComponent(ShanghaiWindy.Core.VehicleHatchAttachmentMonoComponent)/hatchAttachmentSlot/attachment/doubleSidedMeshes/Length"
    },

    }
