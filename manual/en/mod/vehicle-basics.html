    Start with a Blender model and finish with an installable tracked vehicle with one turret. Each section shows where to work, which assets to assign, and how to check the result. You can practice with simple geometry and replace it with a finished model once the workflow works.

    1. Prepare the project, model, and sounds

    1. Follow Project setup to open the SDK project in the required Unity version. Resolve any compilation errors in the Console before opening the mod tools. Check the Console first if a menu is missing.
    2. Prepare a visual model and a separate damage model in Blender. You can author base-color and normal textures in tools such as Substance 3D Painter and Photoshop. Gather engine start, idle, and running audio and near and distant firing audio. For the first test, you can reference compatible FMOD configurations already in the SDK.
    3. Create a folder for this vehicle in Unity's Project window, with subfolders for models, materials, and the collision prefab. Keep your source files. When re-exporting an existing FBX, keep its path and .meta file to preserve the Unity references.

    2. Organize and export the Blender model

    Keep one root object in Blender's Outliner. Select the child, Shift-select its parent, and use Ctrl+P → Object (Keep Transform). To separate part of a mesh, select its faces in Edit Mode and use P → Selection. Put object origins at their actual pivots so the parts rotate around their own axes in Unity.

    Node under the model root What to put there
    MainBody The hull mesh.
    Turret → Gun → Dym Turret, gun elevation node, and recoiling barrel. Nest all three. Place the turret origin at the turret ring and the gun origin at its elevation pivot. The barrel points forward.
    LeftWheel and RightWheel Empty grouping objects. Name the road wheels l_1, l_2… and r_1, r_2… and place their origins at the axles.
    LeftUpperWheel and RightUpperWheel Empty groups for the return rollers. Put each side's rollers in its own group, using names such as lu_1 and ru_1. The current builder orders the wheels by their front-to-back position.
    LeftTrack and RightTrack Static track meshes or their placeholders. You will set up moving track links and their path later.
    1. Model to scale in meters. Select the objects and choose File → Export → FBX. The original guide used Scale 1.00, Apply Scalings → FBX Units Scale, Forward → −Z Forward, and Up → Y Up. In Unity, verify +Z forward and +Y up, then measure the hull against a known dimension. See Correct model axes in Blender.
    2. Export a separate, low-poly damage model. Split plates by armor thickness, material type, and moving part. Each plate gets its own thickness in Unity and belongs under the part it moves with. Separate the internal modules too. Follow the damage-model naming conventions.
    3. For a small first vehicle, the original art budgets are a useful starting point. Aim for about 20,000 faces or fewer on the visual model, about four materials, textures at 2048 × 2048 or lower, and about 5,000 faces or fewer on the damage model. Consolidate duplicate materials and simplify hidden surfaces and collision shapes.

    Drag the imported FBX into a Unity scene and expand its root. This KV-2 comes from the vehicle project. Locate MainBody and Turret in the Hierarchy, then expand Turret → Gun → Dym and match the hierarchy to the parts in Scene View.

    3. Set materials and physical collision in Unity

    1. Drop the visual FBX, damage FBX, and textures in the vehicle folder. Preview the visual FBX. Create or select materials compatible with your project's render pipeline and assign separate base-color and normal textures. Put the materials on each mesh under Mesh Renderer → Materials and check the colors and model orientation.
    2. Drag the visual FBX from Project to Hierarchy and expand it. On MainBody and Turret, use Add Component → Box Collider. Use Edit Collider to adjust the size and center. In front and side views, verify that the bottom of the hull collider clears the ground. A collider that extends too low can stop the vehicle from moving.
    3. Drag the model root from Hierarchy into the Collision folder in Project. Use this prefab for MainModel later. The separate armor plates supply the game's penetration hitboxes.

    4. Create and locate the vehicle assets

    1. In Unity, open Framework - 框架 → 0. Home Page and select the Vehicle Creation Guide. Use Open on the first step to reach Vehicle → Vehicle Creation in the GM Editor. You can also navigate directly to that section.
    2. Choose Ground and enter a unique internal name such as Tutorial-Tank. The current tool accepts uppercase and lowercase English letters, digits, and hyphens. You can add a prefix and assign a separate display name later. Click Create Vehicle and confirm.
    3. In Project, open Assets/Res/Vehicles/Ground/Data/Vehicle/Tutorial-Tank/ and find the assets below. Enter the same internal name in the guide to jump to each file.
    Generated asset Where you use it
    Tutorial-Tank.asset (VehicleInfo) Set the display name, rank, nation, and thumbnail. Add this asset to the mod build pipeline.
    Tutorial-Tank_VehicleHitBox.asset Assign external armor, internal modules, and the generated damage prefab.
    Tutorial-Tank_VehicleTextData.asset Configure basic, movement, firing, and turret parameters.
    Tutorial-Tank_VehicleData.asset Bind the models and data, edit key nodes, and build the vehicle prefab.
    Tutorial-Tank_WheelCollider.prefab and Tutorial-Tank_VehicleTrack.asset Supply the movement configuration with wheel colliders and dynamic tracks.

    5. Generate and configure the damage model

    1. Select VehicleHitBox in Project. Drag the damage FBX into External Armor Model. If you made a separate model for the internal modules, assign it to Internal Module Model. You can assign the visual prefab to Refer Model as a positioning reference.
    2. Click Create Prefab, then Open Edit Mode. Check that Unity opened the correct prefab. Click Generate External Armor to generate the plates. If you assigned an internal model, click Generate Internal Armor to generate its modules.
    3. Select a plate in Hierarchy and inspect the thickness and armor type in its HitBox component. Move the plate under HitBox/Main, HitBox/Turret, HitBox/Gun, or HitBox/Dym to match the part it moves with. See damage-model naming and import for the supported names and examples.
    4. Select a module type and preset in the editor, spawn it, and move it into position. Use the same four groups under InternalModule to attach it to the correct part. You can set each module's HP in its InternalModule component. To assign HP in bulk, set the total and any per-type overrides on VehicleHitBox, then use Auto Assign Internal Module Hit Points.
    5. Tick the roles on crew modules. To support module mode on a tracked vehicle, check for commander, driver, gunner, radio operator, and either loader or autoloader. You can leave module mode off for the first basic drive test and enable it after configuring the interior.
    6. Select the ammo rack's InternalModule. Add bounds and resize them to cover the corresponding ammo volume. Click Create Ammo Cache, or use Multi-Update Ammo Model Cache in the HitBox editor for several racks. Verify that every bound has a cached mesh.
    7. Save the prefab with Ctrl+S and leave Prefab Mode. Check that VehicleHitBox still references the generated prefab.

    Compare the two models in Scene View. The KV-2 visual model keeps the paint and details. The orange damage model is split into armor regions for damage and armor inspection. The two meshes are spaced apart in the illustration. Keep their origins and orientations aligned when setting up the vehicle.

    6. Set vehicle information, shells, audio, and parameters

    1. Open VehicleInfo and set the display name and rank. Match the nation in VehicleTextData. Packing copies the nation from the detailed parameters. See Vehicle thumbnails to assign a picture for the vehicle list.
    2. For the first test, assign compatible VehicleEngineFmodSoundData and BulletFmodSound assets. To make your own, import the recordings into a compatible FMOD project. Author engine start and running events with idle and acceleration sounds, and configure the firing event for near and distant sounds. Build and refresh the banks, then bind events with the picker. Fire Near and Fire Far were fields on the old audio assets. FMOD project setup
    3. Open VehicleTextData and use the bullet editor at the bottom of the Inspector to create a shell. You can also use a suitable shell asset already in the project. Pick the Bullet VFX for its shell type. Add the shell to the ammo list under Fire, check for empty entries, and assign a firing sound.
    4. Set the parameters below. Start with one gun, one ammo type, and standard reload. Test those before trying a more complex weapon.
    Tab What to configure
    Base Expand the base parameters and set hull HP, nation, and view range. Starting with defaults limits the number of variables in the first test.
    Movement Use the track controller. In PTCParameter, set mass in kg, maximum torque, forward and reverse speed, and engine audio. Verify the generated TankWheelCollider and Track Data references.
    Fire In TFParameter, set caliber in mm, standard reload time, shot interval, ammo capacity, recoil scale, firing sound, shells, and dispersion. If you assigned shared gun data, edit those settings on the shared asset.
    Turret In MTParameter, configure traverse range, traverse and elevation speed, and maximum elevation and depression. If you assigned shared turret data, configure it there.

    The optional Tanks.gg tools are still in VehicleTextData. Set tanksGGName and use Import spread data from tank gg to retrieve dispersion data. The broader override changes several existing settings, so save the asset in Git or make a backup first. The service may be unavailable. Review the imported values and fill in the remaining fields. VehicleTextData fields and screenshots

    7. Bind the main model and position the firing nodes

    1. Select VehicleData. Assign the collision prefab from section 3 to Model Data → MainModel. Check that VehicleTextData and HitBox refer to this vehicle's assets.
    2. Click Edit to position the nodes marked with orange icons in Scene view. Move the firing and muzzle-effect points to the muzzle with forward orientation. Check the camera, center of gravity, engine sound, and exhaust nodes too. Press K in Scene view after adjusting the nodes to save their positions and rotations.
    3. Click Unlock Inspector. Check the selected asset and reopen the editor if needed to confirm that the positions were saved.

    8. Set up wheel colliders and moving tracks

    1. Drag the visual prefab and the WheelCollider prefab into the scene. Compare the collider radius and suspension travel with the visible wheels. Save overrides to the correct prefab with Overrides → Apply or Apply to Prefab on the edited value. You can also edit and save the prefab in Prefab Mode.
    2. Start with the generated defaults. The current template uses Suspension Distance 0.2, Spring 205000, Damper 14500, and Target Position 0.5. The four Forward Friction slip/value fields are 1, with Stiffness 1.7. In Sideways Friction, Extremum Slip/Value are 1.2, Asymptote Slip/Value are 1, and Stiffness is 4. Tune after testing your own mass and wheel size. Wheel settings and screenshots
    3. Select VehicleTrackData and assign one track-link prefab to TrackMesh. Use LeftTrackMesh if the left side uses a different shape. Start with the default TrackDistance of 0.12 and adjust it against the actual link length. Leave the generated suspension data in place.
    4. Click Edit Track in the VehicleData Inspector. If you opened the track asset's editor directly, assign the vehicle edit object to Target Edit Object, then click Load Suspension Data. If the edit object is missing, return to VehicleData and enter edit mode to generate it again.
    5. View the wheels from the side. Use Create Node in order around the loop, under the road wheels, over the return rollers, and around both ends. Temporarily hide damage geometry or static tracks if they obscure the path.
    6. Click Preview Track and check link orientation, corners, and spacing on both sides. Use Update Preview after changes. Finish with Save and Unlock Inspector and check the track reference on the vehicle. Track IK and suspension guide

    The KV-2 example below uses the track data from the vehicle project. Orange dots mark the path nodes and the cyan line connects them into a loop. The guide is shifted slightly outward for visibility. On your own vehicle, run the path along the bottom of the road wheels, around both end wheels, and across the top to close the loop.

    9. Cook the vehicle prefab

    Select VehicleData and click Pack. Cooked Output controls whether the generated prefab goes into the shared Cooked folder or beside the data asset. Check that VehicleInfo resolves to the output. Pack again after changing the visual model, colliders, damage model, wheel setup, or positions of the edit nodes. Confirm that the prefab exists before building the mod.

    10. Build, install, and test the mod

    1. In the GM Editor, open Mod Build → Create Mod Package. Use a distinct name such as Vehicle-Tutorial-Tank. Open ModPackageBuildPiplineData and drag this vehicle's VehicleInfo into Linked Objects. Verify the associated Linked Mod Package.
    2. Use File → Build Settings or Ctrl+Shift+B and switch to the target platform. Verify the active platform, then build the linked resources from the pipeline. In ModPackageData, fill in the name, description, author, and version, then click Package Now. Rebuild the linked objects and package again whenever you change platforms.
    3. Find the resulting .modpack under Build/Mod-Package/<platform>/. Check the target and follow Install mods. Use the Windows build for a Windows driving test. Check the build result for the exact file path.
    4. Open the Vehicle Playground, find the new vehicle, and check that it renders and the hull clears the ground. Test forward and reverse movement, steering, tracks, turret traverse, elevation, firing, and reload. Then test damage and make sure the armor and modules line up with the model.

    11. Try variants after the basic tank works

    Variant How to extend the basic tank
    Wheeled vehicle If it still uses the track controller, keep the LeftTrack and RightTrack placeholders. Configure the wheel colliders and review the wheel and track control differences.
    Slot gun (old M3 Stuart example) Use standard fire, enable Has Slot, and set Slot Count and Slot Duration. The old example used 5 and 3.35. Check the burst and reload timing in the playground.
    Drum (Progetto 65 example) Set Fire State to Drum. Configure Fire Duration and Reload Times. The old example used 2 seconds and [12.4, 10.3, 8.6, 6.8]. Verify reload at each stage.
    Magazine (Bat 25t-style example) Choose Advance. In Advance Fire Class, set the short reload, long reload, and rounds per magazine. The old example used 2 seconds, 33 seconds, and 4 rounds.
    Multiple turrets (BMD-1 and T-35) The BMD-1 example used a secondary weapon for missiles. In the T-35 example, SubTurret01 → SubGun01 → SubDym01 is under the root. The other three secondary turrets use suffixes 02, 03, and 04. Set the turret path from the model root, the gun path from its turret, and the barrel path from its gun. Check muzzle and effect offsets on each.
    Twin barrels (ST-II) The old hierarchy put SubTurret → SubGun → SubDym under Turret/Gun. Put the second barrel's pivot at its breech. The example used Turret/Gun/SubTurret for the turret path and SubGun and SubDym for the relative paths. Legacy multi-turret setup

    The old example values illustrate the controls. Tune them for your own mod after testing. For a new multi-turret vehicle, see the current fire-system fields in VehicleTextData. If the model is invisible, the gun points the wrong way, or the vehicle is missing after installation, see vehicle development troubleshooting.
