    Start with a Blender model, then build, package, and test-drive a single-turret tracked tank named Tutorial-Tank. The tables give values you can use for a first test. The KV-2 illustrations show the same hierarchy and asset relationships on a finished vehicle.

    1. Prepare the project, model, and sounds

    1. Follow Project setup to open the SDK project in the required Unity version. Resolve any compilation errors in the Console before opening the mod tools. Check the Console first if a menu is missing.
    2. Prepare a visual model and a separate damage model in Blender. You can author base-color and normal textures in tools such as Substance 3D Painter and Photoshop. Gather engine start, idle, and running audio and near and distant firing audio. For the first test, you can reference compatible FMOD configurations already in the SDK.
    3. Create a folder for this vehicle in Unity's Project window, with subfolders for models, materials, and the collision prefab. Keep your source files. When re-exporting an existing FBX, keep its path and .meta file to preserve the Unity references.

    2. Organize and export the Blender model

    Keep one root object in Blender's Outliner. Select the child, Shift-select its parent, and use Ctrl+P → Object (Keep Transform). To separate part of a mesh, select its faces in Edit Mode and use P → Selection. Put object origins at their actual pivots so the parts rotate around their own axes in Unity.

    Node under the model root What to put there
    MainBody The hull mesh.
    Turret → Gun → Dym Turret, gun elevation node, and recoiling barrel. Nest all three. Place the turret origin at the turret ring and the gun origin at its elevation pivot. The barrel points forward.
    LeftWheel and RightWheel Empty grouping objects. Name the road wheels l_1, l_2… and r_1, r_2… and place their origins at the axles.
    LeftUpperWheel and RightUpperWheel Empty groups for the return rollers. Put each side's rollers in its own group, using names such as lu_1 and ru_1. The current builder orders the wheels by their front-to-back position.
    LeftTrack and RightTrack Static track meshes or their placeholders. You will set up moving track links and their path later.
    1. Model to scale in meters. Select the objects and choose File → Export → FBX. The original guide used Scale 1.00, Apply Scalings → FBX Units Scale, Forward → −Z Forward, and Up → Y Up. In Unity, verify +Z forward and +Y up, then measure the hull against a known dimension. See Correct model axes in Blender.
    2. Export a separate, low-poly damage model. Split plates by armor thickness, material type, and moving part. Each plate gets its own thickness in Unity and belongs under the part it moves with. Separate the internal modules too. Follow the damage-model naming conventions.
    3. For a small first vehicle, the original art budgets are a useful starting point. Aim for about 20,000 faces or fewer on the visual model, about four materials, textures at 2048 × 2048 or lower, and about 5,000 faces or fewer on the damage model. Consolidate duplicate materials and simplify hidden surfaces and collision shapes.

    Drag the imported FBX into a Unity scene and expand its root. This KV-2 comes from the vehicle project. Locate MainBody and Turret in the Hierarchy, then expand Turret → Gun → Dym and match the hierarchy to the parts in Scene View.

    KV-2

    3. Set materials and physical collision in Unity

    1. Import the visual FBX, damage FBX, and textures into Project. In the visual FBX's Model tab, start with Scale Factor = 1. Keep the FBX units and hierarchy and leave Generate Colliders off. Enable Read/Write in the damage FBX's Model tab so the damage mesh can be read. Click Apply, then check that the root instance scale is 1, 1, 1 and the muzzle points along +Z. Compare the hull with a one-metre reference cube.
    2. In Project choose Create → Material and select a compatible vehicle shader. Assign the color texture to Base Map. Import the normal texture as Normal map, then assign that texture in the material. Set the hull, wheel, and track slots under Mesh Renderer → Materials. If the material appears pink, check its shader and the project's render pipeline.
    3. Expand the model in Hierarchy. Add a Box Collider to the solid hull and turret meshes, with Is Trigger off. Use Edit Collider to size each Center and Size. Check the shape from the front and side. Cover the solid hull and leave clearance above the road wheels' ground contact points.
    4. Drag the model root into the Collision folder to create a prefab. Use this prefab for MainModel later. The separate damage model supplies the penetration hitboxes.

    4. Create and locate the vehicle assets

    1. In Unity, open Framework - 框架 → 0. Home Page and select the Vehicle Creation Guide. Use Open on the first step to reach Vehicle → Vehicle Creation in the GM Editor. You can also navigate directly to that section.
    2. Choose Ground and enter a unique internal name such as Tutorial-Tank. The current tool accepts uppercase and lowercase English letters, digits, and hyphens. You can add a prefix and assign a separate display name later. Click Create Vehicle and confirm.
    3. In Project, open Assets/Res/Vehicles/Ground/Data/Vehicle/Tutorial-Tank/ and find the assets below. Enter the same internal name in the guide to jump to each file.

    5. Generate and configure the damage model

    5.1 Assign the source models and create the prefab

    1. Select VehicleHitBox in Project. Drag the external armor FBX into External Armor Model. If you have a separate internal module FBX, assign it to Internal Module Model. Before importing, check both source models against the visual model for origin, orientation, and scale. The two source assets in the screenshot are the sample prefabs used by the tutorial's MCP replay.

    1. Click Create Prefab, then Open Edit Mode. Check that Unity opened this vehicle in Prefab Mode. In the lower part of the separate HitBox Editor window, click Generate External Armor. If you assigned an internal FBX, click Generate Internal Armor as well. Both buttons add objects to the current prefab. For a reimport, back up the prefab and remove the existing nodes you intend to replace first.

    5.2 Check the armor plates and module hierarchy

    1. Expand HitBox/Main in Hierarchy and select the teaching tank's HullFront_65. Check the armor type and the 65 mm thickness in its HitBox component. Check that HitBox/Main, HitBox/Turret, HitBox/Gun, and HitBox/Dym correspond to the hull, turret, gun elevation, and recoil respectively. Source groups such as HitBox_Main and HitBox_Turret can be matched automatically. If a mesh stays under the newly imported root, drag it into the corresponding group while keeping its position relative to the vehicle. See damage-model naming and import.

    For plates that record which areas have already been used after a hit, configure the corresponding HitBox using the reactive armor guide.

    1. In the HitBox Editor, select a module type and a preset, place it, and move it into position. Use the same four groups under InternalModule. The internal source model can use Module_Main, Module_Turret, and the equivalent group names for automatic placement. Set individual HP values in each InternalModule component. To assign HP in bulk, set the total and any per-type overrides on VehicleHitBox, then click Auto Assign Internal Module Hit Points in the editor. Recheck any individual values you want to keep.
    2. Tick the roles on the crew modules. For module mode on a tracked vehicle, check for commander, driver, gunner, radio operator, and either loader or autoloader. You can leave module mode off for the first drive test and enable it after configuring the interior below.
    3. Press Ctrl+S in Prefab Mode to save. After leaving Prefab Mode, confirm that the generated prefab field in the VehicleHitBox Inspector points to the prefab you just edited.

    Configure the internal modules

    1. Open the generated damage prefab and select a mesh under InternalModule. In its InternalModule component, check Module Type, Module Armor (mm), and Hit Point (module HP). For FBX import, use the node names in the first column. For a manually placed preset, enter the values and role flags in the Inspector.

Check CurrentID = 1 and look for the box in Scene View. If there is no box, click Add new bound and use its Scene handles to enclose the ammo mesh. Click Create Ammo Cache after editing. The sample in the screenshot shows Cached Mesh Count 1. For a rack with several visual fill steps, set the bounds separately and rebake. To process several racks, use Multi-Update Ammo Model Cache in the HitBox Editor and check the result for each rack.
    2. To connect a damaged module to a specific gun or turret, check Connectable Vehicle Module at the bottom of the component. Copy the corresponding GUID from VehicleTextData → Module Guid into Connected Vehicle Module Guids. The hierarchy controls where the mesh moves. The GUID identifies the system affected when the module is damaged.
    3. Save the damage prefab with Ctrl+S. Enable Is Module Ready on VehicleInfo, repack, and choose Module Based in the playground. Check that the vehicle can drive, aim, and fire. Switch to the interior view and confirm that the driver stays with the hull and the gunner follows the turret. Shoot a known module with an opposing vehicle and check its HP or damage state.

    6. Set vehicle information, shells, audio, and parameters

    1. In VehicleInfo, set the display name to Tutorial Tank and the rank to 3. Under Spawn Policy, choose Player Pick. Check this when copying a radar or summoned unit. Match the nation in VehicleTextData → Base. Packing copies the nation from the detailed parameters. Add a picture with Vehicle thumbnails.
    2. For the first test, assign compatible VehicleEngineFmodSoundData and BulletFmodSound assets. To make your own, import the recordings into a compatible FMOD project. Author engine start and running events with idle and acceleration sounds, and configure the firing event for near and distant sounds. Build and refresh the banks, then bind events with the picker. Fire Near and Fire Far were fields on the old audio assets. FMOD project setup
    3. Open the bullet editor at the bottom of VehicleTextData. Create a penetrating shell named Tutorial-76mm-AP, choose warhead AP, and set Caliber = 76 mm, Velocity = 650 m/s, Penetration = 90 mm, and Damage = 100. Under Module, enter a projectile mass of 6.5 kg. This solid shot uses 0 for fuse delay and TNT equivalent. Assign a matching AP Bullet VFX, then add this shell as the only entry in the Fire tab's ammo list.
    4. Set the VehicleTextData values below. Save, reselect the asset, and check the values and references. This sample uses local gun and turret parameters. If a shared asset hides those settings, clear Shared Gun Data or Shared Turret Data first.
    Tab What to configure
    Base · PSParameter Health 600 and View Range 360 m. Leave the custom sight point off until the orientation and muzzle position pass your test.
    Movement · PTCParameter Use the track controller. Set mass to 30,000 kg, forward and reverse caps to 35 and 10 km/h, forward and reverse torque to 3500 and 2600, and brake torque to 5000. Use torque-curve points (0, 1) and (35, 0.35). Assign working engine audio, then check TankWheelCollider and Track Data in section 8. See engine, gears and RPM to tune the curve, shift thresholds, or RPM input for audio.
    Fire · TFParameter Choose Standard, reload time 6 s, total ammo 30, and leave Has Slot off. Use a shot interval of 0, recoil scale 1, one AP shell, and a firing sound. Set base dispersion to 0.003. Expand Spread and enter the default settings below for 76 mm. The caliber comes from the shell asset.
    Turret · MTParameter Set the symmetric traverse limit to 180°, turret speed to 18°/s, and gun elevation speed to 12°/s. Enter 20° of elevation and 6° of depression as positive values. Leave direction-specific overrides empty initially. See turret traverse, elevation and stabilizers to set asymmetric limits, clear the hull, or configure stabilization.

    The aiming values in Spread are separate from base dispersion. The defaults for 76 mm are spread 0.35, aim time 1.92 s, movement and turret traverse coefficients 0.14 each, gun movement coefficient 0.11, after-shot coefficient 3, and damaged coefficient 2. Save and check that the Inspector has cleared the spread and projectile damage warnings.

    See gun setup, firing and reloading for magazines, drums, and energy weapons. If the barrel needs to return to a particular angle for reloading, see fixed-angle reload.

    8. Set up wheel colliders and moving tracks

    1. Find the template at VehicleTextData → Movement → TankWheelCollider. Open it in Prefab Mode and select the root with the Wheel Collider component.     Radius / Mass 0.43 m / 320 kg Match the radius to the visible road wheel. This is the mass of one wheel. Set the vehicle mass in section 6.

    9. Cook the vehicle prefab

    Select VehicleData and click Pack. Cooked Output controls whether the generated prefab goes into the shared Cooked folder or beside the data asset. Check that VehicleInfo resolves to the output.     10. Build, install, and test the mod

    1. In the GM Editor, open Mod Build → Create Mod Package. Use a distinct name such as Vehicle-Tutorial-Tank. Open ModPackageBuildPiplineData and drag this vehicle's VehicleInfo into Linked Objects. Verify the associated Linked Mod Package.
    2. Use File → Build Settings or Ctrl+Shift+B and switch to the target platform. Verify the active platform, then build the linked resources from the pipeline. In ModPackageData, fill in the name, description, author, and version, then click Package Now. Rebuild the linked objects and package again whenever you change platforms.
    3. Find the resulting .modpack under Build/Mod-Package/<platform>/. Check the target and follow Install mods. Use the Windows build for a Windows driving test. Check the build result for the exact file path.
    4. In the SDK you can first select VehicleData → Drive (Repack) to open the Vehicle Playground. For an exterior-only test, select Health Based. Select Tutorial Tank and check that it spawns on the ground. Switch to Module Based after you finish the interior.
    5. Use the movement controls to drive forward, reverse, and turn both ways. Release them and check that the tank slows. Watch the wheel contact and the direction and fit of the tracks. Aim away from the hull heading and check traverse and elevation. In the range, fire the first shell. It should leave the muzzle, use one round, and reload in about six seconds. Finally, check the hit feedback.
    6. If an installed package is missing from the selection list, check Player Pick, the damage mode, and the vehicle types supported by the map. If the tank spawns but will not move, check the torque and TankWheelCollider. If the muzzle moves out of place as you turn the turret, recheck the Gun → Dym hierarchy and firing point from section 7 before repacking.

    11. Try variants after the basic tank works

    Variant How to extend the basic tank
    Wheeled vehicle If it still uses the track controller, keep the LeftTrack and RightTrack placeholders. Configure the wheel colliders and review the wheel and track control differences.
    Slot gun (old M3 Stuart example) Use standard fire, enable Has Slot, and set Slot Count and Slot Duration. The old example used 5 and 3.35. Check the burst and reload timing in the playground.
    Drum (Progetto 65 example) Set Fire State to Drum. Configure Fire Duration and Reload Times. The old example used 2 seconds and [12.4, 10.3, 8.6, 6.8]. Verify reload at each stage.
    Magazine (Bat 25t-style example) Choose Advance. In Advance Fire Class, set the short reload, long reload, and rounds per magazine. The old example used 2 seconds, 33 seconds, and 4 rounds.
    Multiple turrets (BMD-1 and T-35) The BMD-1 example used a secondary weapon for missiles. In the T-35 example, SubTurret01 → SubGun01 → SubDym01 is under the root. The other three secondary turrets use suffixes 02, 03, and 04. Set the turret path from the model root, the gun path from its turret, and the barrel path from its gun. Check muzzle and effect offsets on each.
    Twin barrels (ST-II) The old hierarchy put SubTurret → SubGun → SubDym under Turret/Gun. Put the second barrel's pivot at its breech. The example used Turret/Gun/SubTurret for the turret path and SubGun and SubDym for the relative paths. Legacy multi-turret setup
