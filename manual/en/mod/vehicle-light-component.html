    VehicleLightAttachment Guide

    中文 | English

    Run this command at the repository root to replay the examples through the local Unity MCP. The command also captures screenshots in both languages.

    This example configures a circular low-beam light. VehicleLightAttachment is serialized configuration data; VehicleLightAttachmentMonoComponent is the component attached to a GameObject. Field names keep their original C# identifiers.

    1. Create the component and bind the object

    1. Create a light object in the vehicle prefab and add VehicleLightAttachmentMonoComponent. Expand lightAttachmentSlot, then attachment, and assign the light origin to lightTransform. This example uses a separate Tutorial_Light.prefab with a node named LightOrigin.
    2. The same object needs VehicleAttachmentMonoComponent for runtime discovery. Set attachmentSlotType to Specific and assign the light component to specificAttachmentMonoComponent. The project's CustomEditor adds this companion when drawing the light Inspector; the recipe creates and saves it explicitly.

    2. Shape and size

    1. Set the shape to Circle. Circle and HalfCircle show radiusSize; this example uses 0.3.
    2. Rectangles use rectSize instead, and CustomShape uses customShapeRenderers; the existing Light/AuthoringSamples assets are a reference.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "prefab_edit",
    "arguments": {
      "json": {
        "path": "${asset}",
        "mode": "update",
        "component": "ShanghaiWindy.Core.VehicleLightAttachmentMonoComponent",
        "values": {
          "lightAttachmentSlot": {
            "attachment": {
              "lightSizeType": 0,
              "radiusSize": 0.3
            }
          }
        }
      }
    },
    "expect": {
      "equals": {
        "ok": true
      }
    }
  }
]

    3. Appearance and visibility

    1. Set lightType to LowBeam, baseColor to white, and emissionColor to HDR white with intensity 3.5 as in this example.
    2. Keep isAlwaysVisible = true and isBlinker = false, and turn off isAutoNaming. Enabling isBlinker reveals frequency and phase fields. The defaults, blinkerFrequency = 1 and blinkerStep = 0.5, are examples rather than the only working values.
    3. lensEmitters contains lens-glare sampling nodes, up to eight entries; beamOrigin specifies a separate beam origin. Leave both empty for this basic Circle setup. These fields are distinct from Unity Light components.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "prefab_edit",
    "arguments": {
      "json": {
        "path": "${asset}",
        "mode": "update",
        "component": "ShanghaiWindy.Core.VehicleLightAttachmentMonoComponent",
        "values": {
          "lightAttachmentSlot": {
            "attachment": {
              "lightType": 0,
              "baseColor": {
                "r": 1,
                "g": 1,
                "b": 1,
                "a": 1
              },
              "emissionColor": {
                "r": 3.5,
                "g": 3.5,
                "b": 3.5,
                "a": 1
              },
              "isAlwaysVisible": true,
              "isBlinker": false,
              "isAutoNaming": false
            }
          }
        }
      }
    },
    "expect": {
      "equals": {
        "ok": true
      }
    }

]

    4. Verify

    1. Check the object binding to lightTransform, that the companion runtime components were saved, that the Circle radius and colors were written, and that lensEmitters has at most 8 entries; Inspector screenshots show field locations and values, not runtime behavior, so look at the light in game once as well.
