    Setting up a mod mirror site

    中文 | English

    A mirror publishes permitted workshop archives as a directly downloadable folder. It reduces load on the official downloader and still gives players the same packages when the official site is unstable. Keep archive integrity, platform ownership and filenames unchanged.

    History: the old JSON list

    The earlier setup used a public list as the mirror index:

    https://dl-workshop.windyverse.net/packages/files_list.json

    That JSON recorded mod names, update dates and download links, and the service refreshed it every 12 hours. A companion Python helper downloaded every mod from the list; it depended on requests and tqdm, tracked addresses in downloaded_files.json, and staged partial downloads in tmp. Those are descriptions of that period, not something to copy verbatim: today you can take the archives directly and treat the index as background only.

    A GET on that address returned HTTP 404 on 2026-11-18. Since then it describes the shape of the old approach rather than the source or authoritative list of mirror content.

    Archive only permitted workshop archives

    Publish only workshop archives you are allowed to redistribute. Keep each download as it is: do not rename or repack the archive, and do not copy packages from another platform to fill a folder.

    packages/
  android/
  win64/
  ios/

    Use one folder per platform and keep the original filename of each platform's .modpack build. Keep any matching .modpack.json so readers can check the platform, version, GUID, and content metadata. The full file manifest is in package.json inside the archive.

    Use NetDisk as a mirror

    With UC NetDisk as an example, let the client sync the packages folder to the cloud automatically. Share that folder only after synchronization finishes, and share it read-only so readers cannot delete or edit the source directory. Point the share at packages alone, not at temporary folders produced during the run.

    Static hosting alternative

    You can also serve the packages directory through Nginx or another static host. To preview the layout locally, run this command in the parent directory of packages:

    python -m http.server 8080 --bind 127.0.0.1

    Open http://127.0.0.1:8080/packages/win64/, download a real file, and check the path and filename. Press Ctrl+C to stop the preview. Use the same folder layout on the public host and give readers read-only download links.

    Verify after synchronization

    1. Wait for synchronization or deployment to finish; do not publish the link mid-sync.
    2. Open the share as an ordinary reader and download a sample .modpack, confirming that no login or special permission is needed.
    3. In PowerShell run Get-FileHash -Algorithm SHA256 -LiteralPath "<file path>" separately on the source and downloaded copy. The hashes should match. If a .modpack.json exists, also check the platform, version, and GUID.
    4. Once verified, point players to Install mods so they can stage the package in the game's install queue.

    A mirror only serves installation packages, not development tools. The public SDK is a development project; see project download links for how to get it.
