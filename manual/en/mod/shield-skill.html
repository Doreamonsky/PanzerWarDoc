    This tutorial starts with basic shield parameters, then demonstrates a custom model in a separate prefab. armor is assigned to each shield hitbox's HitBox.Armor. It is not a health pool of absorbable damage.

    1. Create a skill slot

    Add an entry to skills under CrewData.upgradableSkillContents and set friendshipRequirement = 0. Choose CrewSkillBuff for crewSkillRef, then EnergyShieldSkillConfig for its crewSkill. The configuration's version must equal the current GetVersion(), which is 3. See the commander tutorial for basic setup.

    The teaching commander reuses Aino's valid portrait references without changing that source commander. Configure your own portraits for production content; valid portrait references are required for packaging.

    3. Configure the shield

    Expand energyShieldInfo and set duration = 10, armor = 200, distance = 15 and sizeScale = (1,1,1). shieldType defaults to Box; alternatives are Sphere and the later Custom example. The image shows the final custom configuration.

    The position follows the turret position plus forward * distance. Box follows the turret's facing; Custom uses isCustomModelFacingForward to control this. After loading, the code binds a shield armor group, assigns the configured Armor to its hitBoxes and marks them as intermittent armor. Removal unbinds that group and returns the resource.

    4. Configure a custom prefab and resource name

    This example copies the official EnergyShield.prefab to Tutorial_Shield.prefab. Preserve EnergyShieldMonoComponent on its root. Check that aabb references VehicleHitBoxAABBComponent and hitBoxes references valid shield HitBox components. Preserve those bindings and colliders when replacing the art. Missing references are not a valid shield setup.

    Create ManualNameBuildPiplineData. In bundleNameMaps, assign the prefab to bundleObject and use a name plus variant for bundleName, such as tutorial-shield-shared.prefab. Add this naming asset to ModPackageBuildPiplineData.linkedObjects. The current collector splits the name at dots; the example uses exactly one dot.

    Set shieldType = Custom and copy the same complete resource name into customModel. It is a runtime resource key, not a project file path. isCustomModelFacingForward defaults to true. The recipe creates a distinct key per run to avoid teaching-package collisions.

    5. Save, check and build

    Save the configuration, check its version, model references and naming pipeline, then build and verify the Windows teaching package. This does not install or publish content.

    The skill registers only for offline VehicleInitSystem receivers. Duration, penetration interactions and visuals still need verification in an offline match with commander buffs enabled. The recipe does not execute those game tests.
