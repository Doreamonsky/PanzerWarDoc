    VRM characters are prepared with the VRM plugins inside Unity. Set up the model and its bone reference points first, export back to the source file, and only then configure the data and pack it.

    1. Import the VRM model

    Drag the .vrm file into Unity's Project window to import it, then drag the imported asset into Hierarchy. The new scene instance has a character root with Vrm10Instance, with the bones and SpringBone chains below it.

    Check the existing Center assignments, especially for a model from another author. Use the steps below if the Center transform is missing or unsuitable.

    2. Fix the SpringBone center references

    1. Press Ctrl+G to open Framework → Editor Tools, search for VRM Util and open the VRM utility.
    2. Expand the character root in Hierarchy and drag its Root child object into Center. Unity assigns the Root object's own Transform.
    3. Drag the character root that owns Vrm10Instance (named DemoVrm in the example) into Vrm 10 Instance.
    4. Click Set Center Transform.

    This writes the Center reference on each SpringBone, so bone physics is computed around the character's real center. Move the character afterwards and check that hair and skirts neither jitter nor fly off.

    3. Export VRM 1.0

    1. Select the character root, then choose VRM1 → Export VRM 1.0... from the top menu.
    2. In the export window, check that ExportRoot is that character root and that Name and Authors on the Meta tab match the license information.
    3. Export to the same path as the source .vrm to overwrite it. If the source is not writable, save a writable copy and rebind that new path in the data. The copy keeps the original model's license.

    Do not drop or edit the license fields in Meta. A re-export should keep the original author, license and allowed uses, and only change what you intended to change.

    4. Configure the VRM character data

    Create a VrmCharacterData in the Project window with Create > A Panzer War - 装甲纷争 > C Config - 配置 > VRM Character - VRM 人物.

    • VRM Model Path: point it at the source file ending in .vrm.
    • GUID: this asset's own identifier. Keep it stable once generated and do not change it for published assets.
    • Height, Radius, Hatch Start Position: current defaults are 1.6, 0.25 and 0.5. The 1.56, 0.15 and 0.84 values in the older screenshots are examples only; measure the model.
    • Desktop Texture Max Size, Mobile Texture Max Size: current defaults are 1024 and 512. None keeps the source PNG/JPG; a specific size compresses to DXT/ASTC and caps the texture at that edge length.

    Hatch operation and crew boarding positions are covered in vehicle hatch fit.

    5. Check before packing

    The build collector copies the source .vrm into the package as <GUID>-model.vrm and applies the texture cap for the active build target. Changes made to the model, bones or materials inside Unity are not packed unless they were exported back into the .vrm.

    So after adjusting bone reference points or license information, finish the export above before starting a build. Before packing, confirm the model path is readable, the GUID is stable, and the desktop and mobile caps suit this release.

    6. Reference it from CrewData

    In CrewData, put the VrmCharacterData GUID from step 4 into the VRM Character GUID field. After packing, check the character's height, radius, hatch start position and texture sizes against the configuration. See crew data for the remaining crew fields.
