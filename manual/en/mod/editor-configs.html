    Custom internal module presets

    中文 | English

    Run this command at the repository root to replay the examples through the local Unity MCP.

    python Docs/Manual/manual/tools/tutorials.py run editor-configs

    The module preset list in the damage model editor comes from two built-in folders and one local configuration array. Lay out the models and register your root folder in the order below to pick your own internal modules from the editor.

    1. Create the module folders

    Create a root folder and module type subfolders in the SDK project, then put the models directly in the subfolders:

    Assets/MyModulePresets/
  Engine/
    EngineA.fbx
  Crew/
    CrewA.fbx

    The current scanner reads only direct *.fbx and *.prefab files under <root>/<type> and does not recurse into subfolders. A type folder name must be the EInternalModuleType member name, case-sensitive, such as Engine, Crew, AmmoShell, Breech, or Transmission. It is not the displayed caption or a string like E 引擎 (Engine).

    Folder name Module
    Transmission Transmission
    Engine Engine
    HeatSink Heat sink
    OilTank Oil tank

    2. Prepare the models

    The model root needs a usable MeshFilter and shared mesh. When a preset is picked, if the model has no collider, ModulePresetUtil.SetupModule adds a MeshCollider that references that shared mesh, plus a kinematic rigidbody. An empty mesh cannot produce the collider.

    You can also ship modules as prefabs, placed as .prefab in the same type folder. The file name is only used for display and does not affect the category.

    3. Register the root folder in the local config

    1. Open Framework → 1. Editor Tools and find Editor Config under 01. ♥ Core Tools.
    2. Add Assets/MyModulePresets to Module Preset Folder. Enter the root folder.
    3. Click Save to write the current Unity project's Assets/EditorStorage.json.

    To edit the file offline, close Unity, then back it up. In the public SDK, the path is UnityProject/Assets/EditorStorage.json. Keep the other keys and add the root to the existing modulePresetFolders array:

    {
  "modulePresetFolders": [
    "Assets/MyModulePresets"
  ]
}
    • Write only the root folder. Do not append /Engine and do not add a trailing slash.
    • Keep the other keys in the file; do not replace an existing config with a minimal object.
    • If the local Assets/EditorStorage.json file does not exist yet, save once from Editor Config.
    • Do not edit this file while Unity is open: EditorStorage.Save writes the whole in-memory object back, so stale values can overwrite your edit.

    4. Use the preset in the damage model editor

    1. Open the target vehicle with the 伤害模型编辑器 - HitBox Editor (VehicleHitBoxEditorWindow) and enter prefab edit mode for that damage model prefab. Outside prefab mode the window only shows a hint.
    2. Press 刷新预设 - Refresh so the scan re-reads the folders.
    3. Pick the target type in 选择的模块类型 - Pick Module Type.
    4. Find its thumbnail. Clicking the thumbnail only pings the asset; the 选择 - Pick button below it instantiates the module into the current prefab.
    5. Adjust position and size, then press Ctrl + S to save the prefab.

    5. Troubleshooting

    Symptom Check
    Custom models are not listed Whether the root is in the array; whether the type folder matches the enum name exactly; whether the file is a direct .fbx or .prefab in that folder; whether you refreshed after the change
    Thumbnail appears but the picked module has no collider Whether the model root has a MeshFilter with a valid shared mesh
    An old model still shows after replacing files Refresh presets, then pick again; confirm the file is not in a subfolder
    Wrong category The file's type folder does not match an EInternalModuleType member

    Built-in example folders

    The current code also scans Assets/Res/InternalDamage/Preset/<type> and Packages/com.shanghaiwindy.middlesharedresources/SharedInternalDamage/Preset/<type> (package constant PackageConst.MIDDLE_SHARED_RESOURCES). Use their files as examples of naming and structure. The middle shared resources package is a dependency package and its sources are not necessarily present in the local Packages folder.

    Related sources: ModulePresetUtil.RefreshModuleMapping, ModulePresetUtil.AddModule, ModulePresetUtil.SetupModule, ModulePresetUtil.DrawModulePreset, EditorStorageInfo.modulePresetFolders, VehicleHitBoxEditorWindow.RefreshPresets, EInternalModuleType.
