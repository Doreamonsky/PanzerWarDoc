    Generate vehicle LODs with InstaLOD

    中文 | English

    LOD generation ships with the mod SDK: its manifest already references the sibling package com.shanghaiwindy.simplygon, which embeds InstaLOD and InstaLodMeshProvider. You do not install anything by hand for the public SDK. The provider hosting LOD work is InstaLOD even though the package and field names say simplygon.

    Ordinary automatic LOD runs when VehicleData.isGenLOD is enabled. Advanced mode additionally requires both isPriorityAdvanceLOD and EditorStorage.useSimplygon to be true; useSimplygon defaults to false, so advanced mode is off until you turn it on.

    1. Enable isGenLOD on the vehicle data. For advanced reduction, authorize the plugin on this machine through Window → InstaLOD, then enable Priority Advance LOD for the vehicle and Use Insta Lod in the editor settings. If authorization fails, turn the editor setting off and repack with ordinary LOD generation. InstaLOD documentation
    2. Repack the vehicle so the pipeline runs.
    3. Inspect the generated prefab and read its LODGroup for the levels that were actually produced. Level count and naming depend on the asset; do not assume fixed node names.

    The screenshot sequence below is historical: package installation and configuration screens come from an older client. Do not treat their labels as current UI promises.

    • Package Manager → Add package from disk, then pick the provider package.json; older SDKs also required provider authorization.
    • Framework → Gm → Editor Config → Use Insta Lod, then Save.
    • Repack, then Open Vehicle Data Tool → View Packed Asset.

    The default shared mesh output is Assets/Res/Cooked/SimplifiedMeshGroup. For a vehicle with a local cook directory, look for SimplifiedMeshGroup under that output directory. The older hull example used node suffixes 100, 75, 50, and 30. Check the generated LODGroup for its actual levels. For mesh editing outside the pipeline, see InstaLOD Studio.
