    Damage model naming rules

    中文 | English

    Run this command at the repository root to replay the examples through the local Unity MCP. The command also captures screenshots in both languages.

    python Docs/Manual/manual/tools/tutorials.py run hitbox-naming-conventions --capture
    Click to expand MCP actionsClick to collapse MCP actions

    Prepare the teaching sample. The recipe provides ${variables}.

    {
  "variables": {
    "external": "${fixture}/Tutorial_ExternalSource.prefab",
    "internal": "${fixture}/Tutorial_InternalSource.prefab",
    "armor": "${fixture}/Tutorial_ImportedArmor.prefab",
    "module": "${fixture}/Tutorial_ImportedModule.prefab"
  },
  "calls": [
    {
      "tool": "invoke",
      "arguments": {
        "path": "static:UnityEditor.AssetDatabase/CreateFolder",
        "args": [
          "${fixtureParent}",
          "${folder}"
        ]
      },
      "expect": {
        "regex": "\\(String\\) [a-f0-9]{32}"
      }
    }
  ]
}

    The damage model editor reads armor and internal module settings from mesh node names. The examples below apply to the vehicle's VehicleHitBox asset.

    2. Generate external armor

    The second segment is the integer armor thickness. Use Inter for spaced armor and React for reactive armor.

    Node name Armor type Thickness
    Plate_100 Normal 100
    Plate_100_Inter Intermittent 100
    Plate_100_React Reactive 100

    In the damage model editor, click Generate External Armor. Move the generated armor under the corresponding parent nodes. See reactive armor for the extra settings on a reactive plate.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "invoke",
    "arguments": {
      "path": "static:ShanghaiWindy.Editor.VehicleHitBoxModelImport/ImportPrefab",
      "args": [
        "${external}",
        "${armor}",
        "false"
      ]
    },
    "expect": {
      "regex": "\\(String\\) [a-f0-9]{32}"
    }
  }
]

    3. Generate internal modules

    In Transmission_120_15, the segments identify the module type, hit points and module armor in that order. Type names are case-sensitive. The importer rounds the two numeric values up to integers. Include all three segments.

    Click Generate Internal Armor, then move the generated modules under their corresponding parents. The numbers in the screenshot match the segments of the node name.

    Click to expand MCP actionsClick to collapse MCP actions 
    [
  {
    "tool": "invoke",
    "arguments": {
      "path": "static:ShanghaiWindy.Editor.VehicleHitBoxModelImport/ImportPrefab",
      "args": [
        "${internal}",
        "${module}",
        "true"
      ]
    },
    "expect": {
      "regex": "\\(String\\) [a-f0-9]{32}"
    }
  }
]

    4. Save and verify

    Save the damage model prefab and check the HitBox and InternalModule fields. The recipe runs the same import processing in isolated prefabs. It verifies all three armor types and thickness values, plus the transmission's hit points and armor.
