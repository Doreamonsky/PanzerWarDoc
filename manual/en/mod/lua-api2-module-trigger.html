    Use this example to play an animation when an internal module such as the ammo rack or engine is destroyed. You could open a hatch or play an engine fire effect. The script responds to module events and avoids reading hit points every frame.

    1. Configure the Animator and attach the script

    1. Open the damage model in Prefab Mode. Put the object to animate inside that prefab, such as a child of the module. Add an Animator and assign an Animator Controller. In Animator → Parameters, choose + → Trigger and add Destroyed. Create the target animation state and set Destroyed as its transition condition.
    2. Import the Lua script below. Add LuaBehaviorMono to the object containing the internal module and assign the script.
    3. Drag the object with the Animator into animator. Set triggerName to the exact spelling and case used in the controller. Save the prefab.

    The script resolves the module in OnVehicleReady. In OnStarted, the damage model might still be assembling. If your test does not trigger the animation, check that the script and module share the same object and that animator is assigned.

    Behavior()
Property = {
    animator = { type = "object", value = nil },
    triggerName = { type = "string", value = "Destroyed" },
}

local ModuleDestroyedTrigger = class("ModuleDestroyedTrigger")

function ModuleDestroyedTrigger:OnVehicleReady(vehicle)
    local module = InternalModuleAPI.GetInternalModule(self.gameObject)
    if module == nil or self.animator == nil then
        return
    end
    local animator = ComponentAPI.GetNativeComponent(self.animator, "Animator")
    if animator == nil then
        return
    end
    local wasDestroyed = InternalModuleAPI.IsDestroyed(module)
    InternalModuleAPI.OnStateChanged(self.script, module, function()
        local destroyed = InternalModuleAPI.IsDestroyed(module)
        if destroyed and not wasDestroyed then
            animator:SetTrigger(self.triggerName)
        end
        wasDestroyed = destroyed
    end)
end

return ModuleDestroyedTrigger

    2. Check state changes and animation

    1. In a test drive, take the module from intact to destroyed. The animation should run once when it enters the destroyed state. Repair it and destroy it again to check that the animation can repeat.
    2. To pick different animations by state, accept (oldState, newState) in the OnStateChanged callback and read GetHitPointRatio(module). For feedback on every damaging hit, subscribe to OnDamaged, whose callback receives the hit points lost.
    3. Pass self.script as the owner, as shown in the example. The game ends the subscription when that behaviour is destroyed.

    The xLua replay checks state transitions and trigger counts. Check the actual Animator transition in game.
