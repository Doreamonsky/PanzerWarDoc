    Collect and package the variants your custom shaders use in the mod.

    Enable Dev Mode

    Turn on Dev Mode in the editor. The build pipeline inspector then shows the Export Shader Variants button; it is hidden in normal mode.

    Create the shader collection

    Create a Shader Collection (ShaderCollectionData) asset and assign it to the pipeline field Shader Variant Collections (shaderCollectionData). This asset only describes what to collect.

    Add shader keywords

    In Shader Keywords, add the source shader and the feature keywords for that shader. Keywords must exist in the shader itself — for example _FOG_LINEAR, _FOG_EXP, _FOG_EXP2 are valid only when the shader declares them. Check the actual keyword names instead of guessing.

    Export the variants

    Press Export Shader Variants. The tool writes a .shadervariants file beside the pipeline's build .asset, built from the pipeline dependency paths.

    Register the generated collection

    Add the generated Unity ShaderVariantCollection to Linked Objects. The settings asset above is its input. Enable both Load Manifest Dependence and Share Dependence Shader on the build pipeline. The collector checks both settings.

    Build and test

    Build for the target platform, then install the result and check fog and material variants in game. Share the shader bundle instead of merging shader source into the .shader file.

    Regenerate after shader changes

    Re-export the variants whenever the shader or its keywords change, then rebuild the modpack.

    The sample creates one variant using the vehicle shader's declared _KEYWORD_ENABLE_CAMO keyword. It verifies the input and output asset bindings and enables shader sharing on the build pipeline.
